# 🔒 安全政策

## 回報漏洞

我們非常重視安全問題。如果您發現安全漏洞，請遵循以下步驟：

### 🚨 安全問題

:::danger 重要
**請勿**為安全漏洞建立公開的 GitHub issue。
:::

請改為私下回報安全問題：

1. **電子郵件**：將詳情發送至 [leonwong282@gmail.com](mailto:leonwong282@gmail.com)
2. **主旨**：在郵件主旨中包含「SECURITY」
3. **詳情**：提供盡可能多的資訊

### 📋 應包含的內容

回報安全漏洞時，請包含：

- **問題類型**（例如：緩衝區溢位、SQL 注入、跨站腳本攻擊等）
- 與問題表現相關的原始檔案**完整路徑**
- 受影響原始碼的**位置**（標籤/分支/提交或直接 URL）
- 重現問題所需的**特殊設定**
- 重現問題的**逐步說明**
- **概念驗證或利用程式碼**（如可能）
- 問題的**影響**，包括攻擊者可能如何利用它

### 🕒 回應時程

- **初步回應**：48 小時內
- **調查**：1 週內
- **修復與揭露**：與回報者協調

### 🏆 致謝

我們感謝安全研究人員，並將：

- 致謝您的貢獻（除非您希望保持匿名）
- 讓您了解進度
- 在我們的安全公告中表彰您（經您同意）

## 安全最佳實踐

### 給貢獻者

- **依賴**：保持依賴項更新
- **程式碼審查**：所有程式碼變更都需要審查
- **測試**：在適用時包含安全測試
- **機密**：永遠不要提交機密、API 金鑰或憑證

### 給使用者

- **更新**：始終使用最新的支援版本
- **設定**：遵循安全設定準則
- **環境**：使用安全的部署實踐
- **監控**：關注安全公告

## 建議的安全實踐

實作您的專案時，請考慮：

- 🔄 **依賴掃描**：啟用自動漏洞偵測（例如 Dependabot）
- 🔍 **程式碼分析**：設定靜態安全分析（例如 CodeQL）
- 🔐 **存取控制**：實作適當的驗證和授權
- 🛡️ **輸入驗證**：清理所有使用者輸入
- ⚙️ **安全預設**：使用安全優先的設定
